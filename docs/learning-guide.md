# 从能运行到能讲清：八周学习与改造路线

这份代码是学习起点。建议每个阶段先跑通一条调用链，再设置断点、故意触发一种失败，最后写下自己的解释。不要在不理解的情况下将“独立设计全部系统”写进简历。

## 第 1 周：HTTP、配置和用户认证

阅读 `config.py → schemas.py → security.py → main.py`。启动 F5，在注册处理函数和登录处理函数设置断点，从 Swagger 提交请求。观察 Pydantic 如何拒绝非法参数，密码怎样变成哈希，JWT 怎样成为后续请求的身份。

自己完成：给“修改知识库名称”增加一个符合业务的校验并验证错误响应；记录 401、403、404、409、422 的区别。理解 JWT 是签名令牌，不是加密的保险箱。当前项目没有邮箱验证、密码找回、刷新令牌和服务器端单个令牌撤销。

验收：用两个账号完成注册/登录，账号 B 访问 A 的知识库失败；数据库中看不到明文密码。

## 第 2 周：数据库和接口设计

阅读 `models.py → db.py`，画出外键关系。打开 `migrations/versions/0001_initial.py`，对照每个索引和唯一约束。解释为什么“先查后写”不能独自解决并发重复插入。

自己完成：在专门的临时数据库练习新建迁移和升级；用两次相同文件上传观察去重响应；解释文件内容哈希和文件名各自的作用。不要对保存了学习成果的数据执行 downgrade。

验收：能说明一次数据库事务的提交边界、失败回滚，以及 `create_all` 和 Alembic 的区别。

## 第 3 周：文档解析和 RAG

阅读 `rag.py`，按“解析 → 按页切分 → 向量化 → 检索 → 引用”逐步调试。修改一份合成材料，观察页码与分块信息。用损坏 PDF、空白文件、非 UTF-8 文本验证错误。

自己完成：准备自己感兴趣的技术领域公开资料，人工写 20 个问题及对应出处。对比两组分块参数，每次只改一个变量。将 hash 的词汇匹配限制写到实验记录，不能把它叫语义理解。

验收：给定一次返回引用，能定位原文件和原文；能解释相似度阈值过高和过低分别造成什么问题。

## 第 4 周：异步任务和恢复

阅读 `tasks.py → ingestion.py`。画出任务状态流转，跟踪领取租约的 SQL 和最终事务。理解文件解析、模型网络请求为什么放在事务外。

自己完成：在测试或隔离开发环境构造一次暂时性向量服务错误，观察有限重试；构造任务租约过期并执行 `recover-jobs`；在处理时删除文档，确认旧结果不能重新发布。优先使用已有测试中的模拟方法，避免依赖真实模型随机故障。

验收：能回答“Celery 重复投递了怎么办”“Worker 写到一半挂了怎么办”“为什么不是 exactly-once”。

## 第 5 周：流式接口与模型协议

阅读 `providers.py`，使用模拟上游的测试理解 SSE 网络分包、用量事件、结束标记、中断和超时。再看 `main.py` 如何把事件转给客户端并保存消息状态。

自己完成：用 `scripts/smoke.py` 的流读取逻辑展示 token、sources、done；观察正常 HTTP 200 与流内失败的区别。如已有模型凭证，先用极少量公开材料验证真实接口，不跳过错误场景。

验收：能解释已开始流式响应后为什么不能自动切换模型，以及客户端断开为什么仍可能计费。

## 第 6 周：权限、边界与测试

从 API 测试中找到所有资源越权用例。梳理上传大小、格式、页数、文本长度、路径和数据库归属检查。理解文档提示词注入和后端访问控制属于不同层次问题。

自己完成：为自己新增的功能补一条能暴露真实错误的回归测试；不要为了增加数量写重复的实现镜像测试。记录一处发现的缺陷、触发条件、修复方式及对应测试。

验收：可以现场演示另一账号访问文档、任务和聊天记录均失败，而不是只保护知识库列表。

## 第 7 周：评测和部署

先运行离线评测理解 JSON，再扩充人工标注题集。将调试集用于参数选择，测试集保留到最终比较。真实模型生成质量需单独人工检查，不由检索命中率代替。

安装 Docker Desktop 后按运维文档启动 PGvector、Redis、API、Worker、Beat。实际运行 `/ready` 和 HTTP 冒烟脚本，保留日志。检查迁移与向量搜索路径，不能用 SQLite 测试代表 PostgreSQL 已验证。

验收：另一台机器按 README 可以复现；能说明本地模式和容器模式在队列、事务、持久化方面的差别。

## 第 8 周：个人改进与答辩

从下面选择一个方向，完成“问题 → 设计 → 改动 → 对照数据”的闭环：

- 检索质量：接入真实中文 Embedding，增加人工题集，对比合成基线与真实资料表现。
- 查询性能：建立有代表性的数据规模，记录 SQL 执行计划，再决定是否引入 HNSW 与召回评测。
- 文档体验：增加一个格式或 OCR 支持，限定资源、错误行为与后台任务流程。
- 服务可靠性：实现有续租的任务租约或事务 Outbox，写清失败模型和测试证据。

这些是练习方向，不是当前代码已实现的功能。选择一个做好即可。最后准备 5 分钟视频、1 页架构说明、实际测试记录和能够如实填写的简历项目条目。

## 最小调试路线

| 想看清的问题 | 设置断点的位置 | 如何触发 |
|---|---|---|
| 身份从哪来 | security.py 的令牌校验 | 带 token 调用受保护接口 |
| 上传为何很快返回 | main.py 上传路由、tasks.py dispatch_job | 上传 examples 文档 |
| Worker 怎样避免覆盖 | ingestion.py 最终提交前的租约检查 | 运行相关任务测试 |
| 哪些文档参与检索 | rag.py retrieve | 调用 search |
| SSE 怎样结束 | providers.py、main.py 流生成器 | 运行 smoke.py |
| 失败怎样重试 | ingestion.py 错误分类与恢复 | 运行故障模拟测试 |

本地线程池可在同一 F5 进程中断点调试。Docker 的 Celery Worker 是独立进程，VS Code 的 API 调试器不会自动附加到它；先通过日志与测试定位，需要时再配置专门的远程调试。
